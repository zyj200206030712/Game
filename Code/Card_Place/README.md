# Card Place（卡阵纪元）

一款使用 Python 与 Pygame 开发的数据驱动放置卡牌战斗游戏。玩家围绕“召唤角色—培养阵容—调整站位—自动战斗—推进关卡”形成成长循环，并通过角色定位、技能冷却与前后排搭配构建阵容策略。

> 项目定位：完整玩法原型 / Python 游戏开发作品 / 客户端与战斗系统方向

## 项目概览

| 项目 | 当前实现 |
| --- | --- |
| 角色与技能 | 38 名可收集角色、38 个配置化技能 |
| 战斗规模 | 支持最多 6v6 的自动回合战斗 |
| 技能系统 | 15 类目标选择方式、8 类效果组件 |
| PVE 内容 | 45 个预设关卡，配置外关卡可继续动态成长 |
| 养成系统 | 召唤、重复角色转碎片、升级、升星、六格布阵 |
| 局外循环 | 挂机金币、关卡奖励、JSON 本地存档 |
| 战斗交互 | 暂停、1/2/5 倍速、撤退、战报滚动与结算统计 |

## 核心玩法

1. 使用金币进行单抽或十连召唤，重复角色自动转化为升星碎片。
2. 在角色界面进行升级、升星与六格阵位编排。
3. 根据敌方阵容选择前排承伤、后排输出及治疗/控制角色。
4. 进入自动战斗，观察技能冷却、属性增减、控制和阵亡状态。
5. 获胜后领取资源并推进关卡，提升挂机金币产出效率。

## 工程实现亮点

### 数据驱动的技能系统

角色属性、技能、目标类型、冷却和效果参数集中维护在 `config.py`。战斗模块根据配置解释并执行技能，不需要为每个新角色复制一套战斗代码。

- 目标选择覆盖单体、随机、前后排、属性最高/最低、友方群体和阵亡友军等 15 类规则。
- 效果系统组合了伤害、治疗、吸血、复活、增益、减益、控制和免控 8 类能力。
- 单个技能可串联多个效果，并通过优先级和独立冷却支持后续扩展。

### 可追踪的 6v6 自动战斗

战斗采用阵位轮转调度，维护角色生命、技能 CD、临时属性、控制回合与伤害/治疗统计。界面同步提供技能高亮、血条、浮动数字、受击位移动画、彩色战报和胜负结算，使自动战斗过程可以被玩家理解。

### 完整的成长与持久化闭环

实现角色召唤、碎片转化、等级/星级成长、阵容编辑、关卡奖励和挂机收益，并将金币、关卡、角色养成及阵位信息序列化到 JSON。存档与资源路径基于项目文件定位，可从不同工作目录启动。

### 模块化职责拆分

```text
Card_Place/
├── main.py          # 游戏循环、输入事件、场景状态与界面编排
├── battle.py        # 回合调度、目标选择和技能效果结算
├── models.py        # 角色模型、数值成长、阵容与存档
├── config.py        # 角色、技能、关卡及视觉常量配置
├── ui.py            # 按钮、文本、血条、浮字与图片缓存
└── save_data.json   # 本地进度数据
```

## 面试讲解建议

### 1. 为什么采用数据驱动

早期若把角色技能直接写进条件分支，每新增角色都需要改动战斗主流程。项目将技能拆成“目标 + 冷却 + 效果列表”，新增大多数角色只需增加配置；复合技能也只是多个效果的组合。这降低了角色扩展成本，并把策划数值与执行逻辑分离。

### 2. 自动战斗如何保证状态一致

每次行动先确定阵位和阵营，再检查存活、控制与技能冷却，最后统一执行目标筛选和效果结算。角色的战斗临时状态在开战和复活时集中重置，避免上一局 Buff、CD 或动画偏移泄漏到下一局。

### 3. 数值内容如何持续扩展

角色基础属性通过等级与星级公式计算，前 45 关使用明确配置控制体验；超出配置范围后，基于最后一关阵容自动提升等级，并按关卡间隔增加星级，使原型在没有持续手填关卡的情况下仍可推进。
